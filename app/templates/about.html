About SentientAI

SentientAI is a cybersecurity learning platform built around isolated labs, structured detection, and a human-verified knowledge pipeline.

What SentientAI is

SentientAI is a platform for learning cybersecurity through practice. It provides controlled, isolated lab environments where security researchers and learners can safely explore how attacks work — and how to detect and defend against them.

The platform is not a scanning tool, not a penetration testing service, and not a way to attack real systems. All activity happens inside sandboxed simulations with no connection to production infrastructure.

The Testing Environment

The testing environment is a separate area of the platform, accessible only to approved tester accounts. Inside the testing environment, users can:

  • Browse and launch security labs covering common vulnerability types
  • Submit test inputs against realistic but isolated target applications
  • View structured detection results and telemetry for every interaction
  • Review Sentinel AI analysis that separates observations from inferences
  • Explore the knowledge base that grows from reviewed lab findings

The testing environment looks and feels different from the public website — it is designed for focused, technical security research work.

What Sentinel is

Sentinel is SentientAI's local cybersecurity analysis model. Currently running SentinelSmolLM2-360M-V9, Sentinel analyzes security events from the labs and produces structured assessments.

Sentinel's output always distinguishes between three categories:

  • Observed — What actually happened, based on telemetry and evidence
  • Inferred — What the model believes is likely, based on patterns and context
  • Unknown — What cannot be determined from available evidence

This distinction is fundamental. Sentinel is designed to be honest about what it does and does not know.

How learning works

When an attack is detected in a lab, the system generates a knowledge candidate — a structured lesson capturing what was observed and analyzed. This candidate goes through a review queue:

  1. Lab event generates telemetry
  2. Detection engine and Sentinel analyze the event
  3. A knowledge candidate is created with a confidence score
  4. A human reviewer approves, edits, or rejects the candidate
  5. Approved knowledge enters the platform's learning base
  6. Approved examples can be exported for model training

Nothing becomes "knowledge" without human review. The platform never automatically publishes AI-generated content.

Why labs are isolated

Lab isolation is a hard requirement, not a suggestion. Every lab operates under these constraints:

  • Labs use simulated data — no real user information, credentials, or system files are involved
  • SQL injection labs query fake in-memory databases, not real database servers
  • XSS labs simulate rendering behavior without executing scripts in real browsers
  • Command injection labs use safe simulators — no real system commands are ever executed
  • Path traversal labs operate on virtual filesystems with no access to real directories
  • No lab can reach the host machine, production databases, or external targets

The goal is education and research, not exploitation.
